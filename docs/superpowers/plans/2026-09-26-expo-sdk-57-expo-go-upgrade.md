# Expo SDK 57 Expo Go Upgrade Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `mobile-app` from Expo SDK 54 to SDK 57 and run it with an Expo Go build that matches SDK 57.

**Architecture:** Upgrade Expo one SDK at a time (54 → 55 → 56 → 57), aligning the React Native and Expo module versions at each checkpoint. Preserve and account for the current uncommitted work before changing dependency manifests; use Expo Go only if every required native module is available in its fixed native runtime.

**Tech Stack:** Expo SDK, Expo Go, React Native, npm, Expo Router, Bugsnag, Android/iOS.

**Spec:** User request in conversation: “write a plan on how to upgrade into expo go SDK 57”.

## Global Constraints

- Scope the dependency upgrade to `mobile-app`; do not upgrade the root Vite app or `mobile-admin` as part of this work.
- Preserve all existing user changes. The current worktree is dirty, including changes to `mobile-app/app.json`, `mobile-app/app/_layout.tsx`, `mobile-app/constants/Config.ts`, `mobile-app/context/LocationContext.tsx`, `mobile-app/hooks/data/useJobDetails.ts`, `mobile-app/utils/bugsnag.ts`, and unrelated files. Do not reset, clean, overwrite, or stash these changes without first preserving them.
- Use Node.js 22.13 or later for SDK 57 according to Expo's SDK reference.
- Keep `mobile-app/package.json` and `mobile-app/package-lock.json` in sync; use npm because the app has an npm lockfile.
- Do not delete `mobile-app/android` until confirming it is generated by Continuous Native Generation (CNG), ignored by Git, and contains no unique native edits. It is currently present locally and appears untracked/ignored.
- Expo Go contains a fixed set of native modules. Confirm compatibility of all app dependencies, especially Bugsnag, before treating Expo Go as the target runtime; use an SDK 57 development build if a required native module is unavailable in Expo Go.
- SDK 57 includes React Native 0.86 and React 19.2. Prefer a patched SDK 57 release at or above `expo@57.0.17`, which addresses the release-note-listed Hermes memory and development startup regressions.

## Review Focus

- Existing local edits and generated Android project files: ensure no user work is discarded or regenerated without review.
- Expo/React/React Native package alignment at each SDK checkpoint: `npx expo install --check` and `npx expo-doctor` must pass or have each exception explicitly understood.
- Bugsnag's SDK 57 support: verify compatible `@bugsnag/expo` and `@bugsnag/expo-performance` versions and native-runtime requirements.
- Expo Go native-module coverage: verify the app can launch and exercise location, notifications, maps, secure storage, and other native-backed features in the SDK 57 Go client.
- Android/iOS permissions and app config: verify location/background-location, notifications, router deep links, and startup still behave correctly after the SDK and Go runtime change.
